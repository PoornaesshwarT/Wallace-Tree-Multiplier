## 📖 Overview

This project implements a **4×4 unsigned Wallace Tree Multiplier** that produces an **8-bit product output**. Unlike a conventional array multiplier, which reduces partial products sequentially row by row, the Wallace Tree architecture reduces partial products **in parallel across multiple stages** using Half Adders and Full Adders. This parallel reduction shortens the critical path through the addition logic compared to sequential accumulation.

The design also incorporates **operand isolation**, controlled by an `enable` signal, to reduce unnecessary switching activity in the partial-product and reduction logic when the multiplier output is not required. This directly targets **dynamic power consumption**, which is dominated by switching activity in CMOS logic.

## 🏗️ Architecture

The design follows a straightforward data flow from operand input to final product:

```
   Input A, Input B
          │
          ▼
   Operand Isolation (enable)
          │
          ▼
  Partial Product Generation
          │
          ▼
   Wallace Tree Reduction
          │
          ▼
      8-bit Product
```

**Stage description:**

| Stage | Purpose |
|---|---|
| **Operand Isolation** | Gates the input operands with the `enable` signal before any logic evaluation, preventing switching activity from propagating into downstream logic when disabled. |
| **Partial Product Generation** | Generates the 4×4 = 16 partial-product bits using AND gates between the bits of operand A and operand B. |
| **Wallace Tree Reduction** | Compresses the partial-product bits in parallel stages using Half Adders and Full Adders until only two rows remain, which are then added to form the final product. |
| **Product Output** | Produces the final 8-bit unsigned product. |

---

## ⚙️ Working Principle

1. Two 4-bit unsigned operands, **A** and **B**, are passed through the operand isolation logic.
2. Partial products are generated by ANDing each bit of A with each bit of B, producing 16 partial-product bits arranged by bit-weight (column).
3. Instead of adding these partial products sequentially, the Wallace Tree groups bits of the same weight into sets of three (or two) and reduces them concurrently using **Full Adders** (3:2 compression) and **Half Adders** (2:2 compression).
4. This reduction is repeated over multiple stages until the number of partial-product rows is reduced to two.
5. The final two rows are added together to produce the **8-bit product**.

This parallel reduction strategy is the defining characteristic of the Wallace Tree architecture and is why it is used here in place of a conventional array-based sequential reduction.

---

## 🔋 Low-Power Technique — Operand Isolation

Operand isolation is applied at the input stage using the `enable` signal:

- **When `enable = 1`** → The original operand values (A and B) are passed through to the partial-product generation logic, and multiplication proceeds normally.
- **When `enable = 0`** → The operands are forced to zero before reaching the partial-product and reduction logic.

By forcing the operands to a constant value when the multiplier result is not needed, the downstream combinational logic (AND gates, Half Adders, Full Adders) does not toggle in response to changing input data. Since dynamic power in CMOS logic is directly related to switching activity, this technique reduces unnecessary transitions and lowers dynamic power consumption during idle periods.

## 🧩 RTL Design

The design is structured into the following major Verilog modules:

- **Half Adder** — Performs 2:2 bit compression (Sum and Carry from two inputs).
- **Full Adder** — Performs 3:2 bit compression (Sum and Carry from three inputs).
- **Wallace Tree Multiplier (Top Module)** — Integrates operand isolation, partial-product generation, and the Half Adder/Full Adder reduction network to produce the final 8-bit product.

## ✅ Verification

The design was functionally verified using a **Verilog testbench** applied to the top-level Wallace Tree Multiplier module. The following input combinations were used to check correctness of both the multiplication logic and the operand isolation behavior:

| A | B | Enable | Purpose |
|---|---|---|---|
| 5 | 3 | 0 | Verify operand isolation forces output to zero |
| 3 | 4 | 1 | Basic functional check |
| 7 | 2 | 1 | Functional check |
| 9 | 6 | 1 | Functional check |
| 15 | 15 | 1 | Maximum input value (boundary case) |

These test cases confirm correct multiplication results under normal operation and correct suppression of operand activity when `enable` is disabled.
